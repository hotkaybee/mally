# План развития админки Mally

Документ — что добавить в админ-панель (`/admin`, Filament 4), чтобы магазином
можно было управлять без правки кода и `.env`. Это **план, не код**: каждый
пункт — отдельная задача `MAL-<n>` с тестами по правилам `CLAUDE.md`.

Приоритеты: **P0** — нужно до запуска, **P1** — ежедневная работа и контент
витрины, **P2** — рост и удобство.

> Деньги остаются в **USD** (как требует `CLAUDE.md` и как сейчас работает код).
> Рекомендация L-3 из `logic.md` хранить заказы в сумах — устарела; сумы только
> для показа, со снимком курса в заказе (`exchange_rate`, `amount_uzs`).

## P0 — до запуска

### P0-1. Работа с заказом: статусы, оплата, отмена, история

**Проблема.** Нельзя отметить, что перевод на карту пришёл; отменить заказ можно
только удалением (без следа); неоплаченные заказы держат товар навсегда;
любой статус можно поставить из любого.

**Данные.**
- Статусы: `Новый → Оплачен → Собирается → Отправлен → Доставлен`, плюс `Отменён`
  и `Возврат`. Разрешённые переходы описаны в одном месте.
- Оплата: `ожидает / оплачен / частично / возвращён`, `paid_at`.
- В заказе: `cancelled_at`, `cancel_reason`, `admin_note`, мягкое удаление.
- Таблица `order_events` — кто (админ / бот / система), когда, из какого статуса
  в какой, причина.
- Один сервис смены статуса, которым пользуются и админка, и Telegram-бот.
  Отмена возвращает товар на склад ровно один раз.

**Как выглядит.**
- В карточке заказа кнопки вверху, зависят от текущего статуса:
  «💳 Оплата получена» (заполняет «оплачено» и дату), «📦 Собрать»,
  «🚚 Отправлен» (спрашивает трек-номер), «✅ Доставлен», «❌ Отменить»
  (обязательная причина, подтверждение, красная).
- Поле «статус» из формы редактирования убрать — только кнопки.
- Удалять можно только отменённые заказы и только владельцу.
- В таблице те же действия в меню строки и массовое «Отправлены».
- В Telegram-боте те же кнопки с теми же правилами; каждое нажатие — запись в истории.

**Витрина.** Чек и профиль показывают настоящий статус (экран «Отменён» в чеке уже свёрстан).

### P0-2. Карточка заказа, с которой можно работать

**Как выглядит** — две колонки.
- **Слева** — состав: фото, название, артикул, количество, цена, сумма.
  Себестоимость и маржа — только владельцу.
- **Справа** — блоки:
  - Клиент — имя (ссылка на клиента), телефон (`tel:`), «Написать в Telegram».
  - Доставка — город, адрес, комментарий, трек-номер.
  - Деньги — подытог, промокод, скидка, итог $, курс заказа, итог в сумах, оплачено, статус оплаты.
  - История — лента из `order_events`.
- **Таблица заказов.**
  - Колонки: номер (поиск), клиент, телефон, город, сумма `$` и `сум`, цветные
    бейджи статуса и оплаты, дата по Ташкенту.
  - Фильтры: статус, оплата, период, с промокодом, город.
  - Вкладки со счётчиками: Новые / Ждут оплаты / Сборка / Отправлены / Доставлены / Отменены.
  - Значок у пункта меню «Заказы» — число новых заказов.

### P0-3. Страница «Настройки магазина»

**Проблема.** Карта, контакты, промокод, тексты доставки живут в `.env` и Blade —
менять их может только программист.

**Данные.** Таблица настроек «ключ — значение» (или пакет `spatie/laravel-settings`
с плагином Filament — версию проверить), с кешем. Тексты — на трёх языках.

**Как выглядит** — одна страница с вкладками, доступна только владельцу.
- **Оплата:** номер карты, владелец, банк (Humo / Uzcard), срок оплаты в часах.
- **Контакты:** телефон, email, Telegram, Instagram, адрес, часы работы (ru/uz/en).
- **Доставка:** см. P1-5.
- **Курс:** автоматически с cbu.uz или вручную до даты. Показать текущий курс и
  когда обновлён, кнопка «Обновить сейчас».
- **Уведомления:** chat id админов, какие события присылать в бота.
- **Склад:** порог «мало на складе» по умолчанию.

**Витрина.** Подвал, «Контакты», оформление заказа и чек берут данные из настроек.

### P0-4. Правильные цифры на главной админки

- Выручка за сегодня / 7 / 30 дней — **только оплаченные и не отменённые**, в $
  с подсказкой в сумах.
- Средний чек.
- Блок «Требует внимания»: новые заказы, не оплачены дольше N часов, отзывы на
  модерации, товары заканчиваются.
- Прибыль за 30 дней: (цена − себестоимость партии) × количество — только владельцу.
- График по месяцам — только оплаченные, вторая линия — прибыль.
- «Последние заказы» — с номером заказа и переходом в карточку.

### P0-5. Роли: владелец и менеджер

**Проблема.** Есть только «админ / не админ»; любой сотрудник видит закупочные
цены, карго, наценку и прибыль.

**Данные.** Роль у сотрудника (`владелец / менеджер / кладовщик`), не через
массовое заполнение. Вариант — `spatie/laravel-permission` + Filament Shield
(версию проверить). Права проверяются на сервере (policies), а не только
скрытием кнопок.

**Как выглядит.**

| Раздел | Владелец | Менеджер | Кладовщик |
|---|---|---|---|
| Заказы, клиенты, отзывы, возвраты | ✅ | ✅ | только «к отправке» |
| Товары | ✅ | только просмотр | просмотр |
| Поступления, себестоимость, прибыль | ✅ | ❌ | количества без цен |
| Настройки, сотрудники, журнал | ✅ | ❌ | ❌ |

- Раздел «Сотрудники»: пригласить, назначить роль, заблокировать (вместо
  команды `admin:grant`).
- Включить двухфакторный вход Filament для сотрудников.

> Права администратора и авторизацию Filament отдельно ревьюит Kamron — эта
> задача делается вместе с ним.

### P0-6. Промокоды в базе

**Данные.** Таблица промокодов:
- код;
- тип (процент или фиксированная сумма в $) и размер скидки;
- минимальная сумма заказа;
- лимит использований (всего и на клиента) и счётчик использований;
- период действия;
- активен ли.

Заказ хранит ссылку на промокод; счётчик растёт внутри транзакции заказа.

**Как выглядит.**
- Таблица: код (копируется), скидка, использовано / лимит, период, переключатель «активен».
- Фильтры: активные / истёкшие.
- В карточке промокода — заказы с ним и принесённая выручка.

## P1 — ежедневная работа и контент витрины

### P1-1. Контент товара: галерея, описание, переводы, SEO

Витрина уже умеет показывать галерею, старую цену, «преимущества», «как
использовать» и состав — но данные фейковые, потому что их негде заполнить.

**Данные.**
- Таблица фото товара (порядок, alt) или `spatie/laravel-medialibrary`.
- Название, описание, «как использовать», состав, преимущества — на ru/uz/en.
  Формат как у категорий: колонки `_ru/_uz/_en`. Один механизм на весь проект.
- Старая цена (для вкладки «Скидки»), «хит», «показывать на сайте», порядок.
- Объём, страна.
- `slug`, meta title / description.

**Форма товара — вкладки.**
1. **Основное:** бренд, категория, артикул, видимость, «хит».
2. **Описание:** внутренние вкладки RU / UZ / EN — название, описание (редактор
   с форматированием), как использовать, состав, список преимуществ.
3. **Фото:** несколько загрузок, перетаскиванием менять порядок, первое — обложка,
   встроенная обрезка.
4. **Цена и склад:** остаток и цена (только чтение), старая цена, кнопка «Добавить поступление».
5. **SEO:** slug, meta, превью «как в Google».

**Таблица товаров.**
- Миниатюра и бейдж остатка: «Распродано» — красный, «Мало» — жёлтый.
- Фильтры: бренд, категория, статус, остаток ≤ N, без фото, без описания, без перевода.
- Массовые действия: скрыть / показать, сменить категорию, «хит».

**Витрина.**
- Убрать захардкоженные тексты и запасную картинку `findy.uz`.
- Заработает вкладка «Скидки».
- У каждого товара свои `<title>`, meta и OpenGraph — красивое превью ссылки в Telegram.

### P1-2. Настоящий рейтинг вместо «5.0»

- **Данные:**
  - у товара средняя оценка и число отзывов, пересчитываются при публикации, скрытии и удалении отзыва;
  - у отзыва ответ магазина, кто и когда проверил;
  - фото отзывов хранятся у нас, а не по чужим ссылкам.
- **Отзывы в админке:**
  - в таблице фото, товар ссылкой, звёзды;
  - вкладка «На модерации» по умолчанию;
  - действия «Опубликовать», «Скрыть» (и массово), «Ответить».
- **В карточке товара** админки — рейтинг и список отзывов.
- **Витрина:** звёзды = реальная средняя; нет отзывов — нет звёзд. На странице
  товара — ответ магазина.

### P1-3. Клиенты (простая CRM)

- **Таблица:**
  - колонки: город, число заказов, сумма покупок (оплаченных), дата последнего
    заказа, значки «есть аккаунт» и «Telegram привязан»;
  - убрать колонку `instagram`;
  - фильтры: город, источник, есть заказы, повторные покупатели, заблокированные.
- **Карточка:** вверху цифры (заказов, сумма, средний чек), ниже список заказов,
  заметка менеджера, теги, «заблокировать» (проверяется при оформлении).
- Слияние клиентов — только вручную с записью в журнал (автоматически объединять
  запрещено `CLAUDE.md`).

### P1-4. Склад: списания, сроки годности, история партий

- **Порог «мало».** У товара свой порог «мало на складе», если не задан — из настроек.
- **Списания.** Причины: брак, просрочка, тестер, пересчёт; кто списал. Списание
  проходит через `InventoryService`.
- **Срок годности партии** — косметика портится.
- **В админке:**
  - история поступлений в карточке товара;
  - фильтры поступлений: «есть остаток», поставщик, дата, «скоро истекает»;
  - действие «Списать»;
  - виджеты «Заканчивается» (вместе с распроданными, кнопка «Создать поступление»)
    и «Скоро истекает срок».

### P1-5. Доставка

- **Зоны доставки:**
  - название ×3 языка;
  - способ — Yandex Go, BTS или самовывоз;
  - стоимость в $ или «по тарифу»;
  - бесплатно от суммы;
  - срок;
  - активна ли.
- **В заказе:** зона, способ, стоимость, трек-номер, даты отправки и доставки.
- **Витрина:** при оформлении выбор города и способа, стоимость считает сервер;
  в чеке — трек-номер.

### P1-6. Возвраты

- **Заявка на возврат:** заказ, товары, причина, фото, статус, сумма возврата,
  «вернуть на склад», заметка.
- **Действия в админке:** «Одобрить», «Отклонить» (с причиной), «Товар получен →
  на склад», «Деньги возвращены».
- **Витрина:** кнопка «Вернуть» в профиле у доставленных заказов; текст правил —
  из CMS (P1-7).

### P1-7. Главная страница и тексты сайта (CMS)

Группа меню «Контент»:
- **Баннеры** — заголовок, подзаголовок, кнопка ×3 языка, картинки для компьютера
  и телефона, ссылка, период показа, порядок перетаскиванием.
- **FAQ** — вопрос и ответ ×3, порядок.
- **Страницы** — оферта, конфиденциальность, возвраты, доставка (редактор, ×3 языка).
- **Бренды** — загрузка логотипа, описание, страна, «показывать на главной».
- **Категории** — загрузка иконки, порядок в меню, «показывать в меню».

Главная и меню берут всё это из базы вместо массивов в коде (`match ($locale)`
нарушает правило переводов из `CLAUDE.md`).

### P1-8. Уведомления и входящие

- Колокольчик в админке: новый заказ, отзыв на модерации, мало товара, заявка на возврат.
- Сообщения формы «Контакты» сохраняются в базе: раздел «Обращения» с вкладками
  «Новые / Отвечены» (сейчас они уходят в Telegram и теряются).
- Клиенту — сообщение в Telegram (если привязан) или на email: оплата получена,
  заказ отправлен (с трек-номером), заказ отменён.

## P2 — рост и удобство

- **Журнал действий** (`spatie/laravel-activitylog`): изменения заказов, цен,
  поступлений, списаний, промокодов, настроек, ролей. Вкладка «История» в
  записи и общая страница «Журнал» для владельца. Действия бота пишутся как
  «Telegram-бот (chat id)».
- **Печать:** накладная или чек заказа — логотип, номер, состав, сумма в $ и
  сумах по курсу заказа, адрес, QR на чек. Массовая печать для отгрузки.
- **Импорт и экспорт** (встроенные в Filament):
  - экспорт заказов с составом, клиентов, товаров, оценки склада (себестоимость — только владельцу);
  - импорт товаров и поступлений из CSV.
- **Отчёты** для владельца, за выбранный период:
  - продажи по дням, брендам и категориям;
  - топ товаров по выручке и марже;
  - товары без продаж N дней;
  - эффективность промокодов;
  - доля повторных покупателей;
  - разбивка по городам.
- **Автоматизация:**
  - автоотмена неоплаченных через N часов (товар возвращается);
  - утренняя сводка владельцу в Telegram: продажи за вчера, заканчивающиеся товары, отзывы на модерации.
- **Оттенки и варианты** — отдельный большой этап (меняет корзину, заказ и склад;
  в `logic.md` отложено). До него: один товар на оттенок плюс поле «семейство»,
  чтобы на странице товара показывать соседние оттенки.
- **Мелочи:**
  - ручной заказ из админки считает цены через тот же `OrderService` (сейчас цену можно вписать любую);
  - «Дублировать товар»;
  - ссылка «Открыть на сайте»;
  - sitemap;
  - брошенные корзины (нужны корзины в базе).

## Дизайн админки

**Бренд.**
- Название «Mally», логотип (светлый и тёмный варианты), favicon.
- Основной цвет — как на витрине (розово-бежевая гамма вместо жёлтого Amber),
  тот же шрифт, что на сайте.
- Сворачиваемое боковое меню, быстрые переходы без перезагрузки (SPA-режим
  Filament).
- Глобальный поиск по номеру заказа, артикулу и телефону.

**Меню по группам** (с отдельной иконкой у каждого раздела):

| Группа | Разделы |
|---|---|
| Продажи | Заказы, Возвраты, Промокоды |
| Каталог | Товары, Бренды, Категории |
| Склад | Поступления, Списания |
| Клиенты | Клиенты, Отзывы, Обращения |
| Контент | Баннеры, FAQ, Страницы |
| Система | Настройки, Сотрудники, Журнал |

**Тексты и форматы.**
- **Переводы:**
  - все подписи — нормальным русским текстом, ключи во всех трёх `lang/*.json`;
  - сейчас часть подписей — сырые ключи (`category_id`, `category.name`);
  - заголовки во множественном числе там, где нужно единственное («Создать Товары»).
- **Форматы:**
  - даты — по времени Ташкента;
  - все суммы — в формате `$`.
- **Пустые таблицы** — с понятным текстом и кнопкой действия («Пока нет
  заказов», «Добавить первый товар»).
- **Язык админки** — свой переключатель ru / uz / en, отдельно от языка витрины.

**Удобство оператора.**
- Цветные бейджи статусов по всему интерфейсу: новый — синий, ждёт оплаты —
  жёлтый, отправлен — фиолетовый, доставлен — зелёный, отменён — серый/красный.
- В таблицах — миниатюры товаров, копирование телефона и номера заказа в один клик.
- Главные действия (оплата, отправка, отмена) — крупные кнопки в шапке карточки,
  опасные — красные с подтверждением.
- На телефоне: таблица заказов складывается в карточки, кнопки статусов доступны
  одной рукой — менеджер часто работает с телефона.
